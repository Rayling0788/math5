# 编程实现与数据图表生成

本 skill 承接 `2analysis-modeling`。目标是把 `reports/ANALYSIS_MODELING_REPORT.md` 里的模型和算法落实为可复现程序，跑出可信结果，并生成论文中需要的数据型图表。

## 数学建模规范参考

如需领域判断，读取 `../_references/math_modeling_norms.md` 中的“题型防错速查”“代码实现与结果”“编码阶段常见错误”和“图表与可视化”小节。该文件只作为规范知识库，不新增本阶段的固定产物。

## 阶段边界

- 本阶段负责：代码、实验运行、结果、结果表、数据驱动图表，以及由真实模型参数生成的几何、结构、局部坐标和约束示意图。纯符号解析几何图若不承载计算数值，可使用 LaTeX/TikZ 生成矢量线稿，并单独登记为 `generator=latex`。
- 本阶段不负责：技术路线图、算法流程图和抽象系统架构图。这些交给 `4drawio`。参数化模型示意图不能转交 DrawIO 或手工绘制。
- 本阶段不写论文正文，只为 `5writing` 提供可信数值和图表资产。


### Step 1: 代码结构

按 `plan.md` 中"项目目录结构"创建 `code/` 和 `figures/` 骨架。首先实现并实际运行统一入口 `run_all.m`（或项目既有等价入口）：它必须识别所有问题，支持按问题选择运行，并让尚未实现的问题明确返回 `NOT_RUN`，不能直接报 “ALL 未实现” 或输出模板示例值。

在深入任何单个求解器前，先让以下最小闭环成功一次：

```text
run_all -> 一个真实结构化结果 -> 一张图或一张表 -> 论文模板 -> 编译
```

后续只替换闭环内相应组件，不拆掉已工作的接口。


### Step 2: 逐子问题实现

按真实依赖实现；无 blocking 边的问题可并行，不必等待前一问的认证层。每问先完成 `fast_contract`，再决定是否进入 `certification_upgrade`。

每个子问题必须完成：

1. 读取所需数据。
2. 实现模型或算法。
3. 验证约束。
4. 输出核心结果。
5. 绘制丰富的图表。
6. 在 `reports/RESULTS_REPORT.md` 中写清楚方法、关键数值和校验结果。

动态、迭代、随机、优化或场求解器在完整运行前必须先执行：10 步/短时窗或小网格，低/正常/极端三组输入，有限值与实数检查，量纲和数量级检查，边界/单调/守恒检查，以及可用时的解析或极限基线。烟雾测试失败只阻塞该任务，不得通过增加迭代规模掩盖错误。

同一高保真门禁最多修复两次。仍失败时保存最小失败日志和复现命令，标记 `FAILED_DIAGNOSTIC`，继续不依赖它的任务。已执行的解析、降阶或参数扫描结果只有在通过根 Skill 的完整交付质量底线后才可标为 `PAPER_USABLE`；仅运行成功、趋势正确或写明局限均不充分。若高保真失败结果直接反驳快速层 claim，则只撤销该 claim 及其阻塞后继，不得继续写入正文。

优化类问题必须先保证可行解，再优化目标值。预测类问题必须做训练/验证划分或合理误差评估。评价类问题必须说明指标方向、归一化方法和权重来源。

预测与分类任务在首次正式拟合前运行一次防泄漏审计，并把结果写入结构化输出：

1. 输出独立评价单位、group ID、fold ID、各折类别数和训练/验证/测试交集，交集必须为空。
2. 缺失值处理、标准化、特征选择、重采样、超参数搜索、堆叠、校准和阈值选择只能在相应训练折内部拟合。
3. 堆叠模型的一级预测必须来自 out-of-fold 预测；禁止加载全数据预训练模型后在名义验证折上直接预测并称为交叉验证。
4. 类别不平衡时同时输出事件率、朴素/规则基线、PR-AUC、召回率或 F 分数、Brier 或 log loss 和校准证据；Accuracy 只能作为补充。
5. 保存每个指标的公式、正负方向、评价单位、场景和聚类不确定性区间。未定义的“预测精度”“准确率”不得进入结果报告。

模型复杂度比较必须包含一个可信简单基线，并在相同无泄漏划分上评价。复杂模型若只提高训练指标，或外推增益区间跨零，保留简单模型并把复杂模型登记为未形成稳定增益。标签拆分、互斥状态编码、类别名称和输出表的类别数必须由同一映射函数生成并断言一致。

随机优化必须保存全部独立运行而非只保存最好一次，报告最优值、均值、标准差、可行率和随机种子；可获得小规模精确解时必须报告最优性差距。没有证书时只写“当前搜索所得最优可行解”，不得输出 `global optimum`。

### Step 3: 结果文件格式


AI 在实现、求解和作图过程中，必须把关键中间过程保存成数据并做好记录，例如清洗后的数据摘要、模型参数、迭代历史、约束检查、灵敏度分析过程、图表所用数据和运行日志。中间数据优先保存到 `figures/` 或 `code/outputs/`，并在 `reports/RESULTS_REPORT.md` 中说明文件用途。

`reports/RESULTS_REPORT.md` 推荐结构：

```markdown
# 计算结果

## 运行环境
## 数据读取与预处理
## 问题一结果
## 问题二结果
## 问题三结果
## 灵敏度分析
## 约束与一致性校验
## 与建模报告的一致性说明
## 可复现运行方式
```

所有数据和图表结果都必须出现在 `reports/RESULTS_REPORT.md` 中引用

同时更新 `results/workflow_state.csv` 的 task 状态、输入/输出指纹、尝试次数、最后命令和下一步。输入指纹和 accepted 输出未变化的任务直接 `SKIP`，不得重复计算。

### Step 4: 生成数据驱动图表

根据 `reports/ANALYSIS_MODELING_REPORT.md` 和 `reports/RESULTS_REPORT.md` 规划图表，生成 PDF 到 `figures/`。

典型图表：

- 预测类：真实值-预测值对比、误差分布、指标对比。
- 优化类：收敛曲线、成本对比、资源利用率、方案前后对比。
- 评价类：综合得分排序、雷达图、热力图、敏感性曲线。
- 数据理解：分布图、趋势图、相关性图、箱线图。
- 几何/机理：真实比例轮廓或剖面、中心线或路径、关键点、局部切向/法向、尺寸链、接触/载荷/边界条件和约束裕度。

图表要求：

- PDF 矢量输出，适合论文。
- 不在图内写大标题，标题交给论文 caption（Typst 的 `caption:` 或 LaTeX 的 `\caption{}`）。
- 中文论文图表使用中文坐标轴和图例；英文论文使用英文。
- 不生成流程图/架构图/路线图。

对几何、碰撞、机构、路径、结构或场问题，至少生成一张与推导直接对应的 MATLAB 模型示意图。图中按需包含：

- 由求解器参数直接构造的对象轮廓、中心线、截面或计算域；
- 具有论文符号的关键点、节点、接触点和候选对象；
- 局部切向/法向、载荷方向、边界法向或坐标轴，并用箭头区分方向；
- 尺寸箭头、数值和单位，以及与公式一致的孔距、宽度、半径、边界或间隙；
- 当前推导真正使用的相交、投影、相切、距离或边界关系。

对“刚体沿曲线运动”或“局部圆弧/接触几何”类图，参考高质量教材式构型图的分析表达，而不是只画整条轨迹：绘制板件或机构轮廓，以实线画活动曲线段，以带下标符号标出相邻节点和连接点，以圆点标出圆心或接触基准，以虚线连接半径、弦或辅助三角形，并用贴合中心线的箭头表示运动方向。若姿态来自求解结果，用 MATLAB 和真实坐标生成；若只解释余弦定理、投影或相切等符号关系，优先使用 TikZ 的正视矢量线稿，避免把解析示意图画成带坐标轴的仿真结果图。两种方式都必须保留可编辑源码、PDF 和 300 dpi PNG。

用户给出的高级构型图只用于提炼画图方法，不表示必须把其中每种构型逐张复刻。应学习其正视或剖视取景、实体轮廓、局部放大、主辅线层级、关键点与公式一一对应等表达方式，再根据本题的真实模型选择需要重画的对象。数据趋势用真实数据图表达，空间或三变量关系用具有真实第三维的 3D 图表达，局部解析关系用正视构型图表达；三类图可以在同一问题中互相补证，但不得机械拼接，也不得为保持风格统一而虚构曲面、厚度或构型。

采用克制的黑灰线稿或低饱和强调色，主对象线宽高于辅助线；局部基向量和尺寸标注只突出关键关系。文字尽量水平，标签与箭头不得压住对象或彼此重叠。2D 能清楚表达时不强制 3D；使用 3D 时第三维必须是真实变量或模型参数，并提供正视/俯视/剖面等辅助视图消除透视歧义。

图表可以由主程序或独立脚本生成，不强制固定脚本名。无论采用哪种方式，都必须保存图表对应的数据来源和生成记录。

图表错误只重跑该图的生成器和受影响页面检查；不要因此重跑模型。先生成每问最关键的结果证据，最终交付前再补齐机制与验证角色，不要为一次性凑齐全部图阻塞最小闭环。
