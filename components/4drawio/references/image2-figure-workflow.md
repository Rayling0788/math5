# Image2 图示工作流

本规则从数模工坊已恢复的 skill、前端入口和本地主程序逻辑整理而来。执行时按原程序条件选图，不自行扩大或缩小范围。

## 1. 固定选图规则

| 图 | 自动触发条件 | 原程序文件名 | 来源材料 |
| --- | --- | --- | --- |
| 总体技术路线图 | 固定候选 | `figures/flowchart.png` | 题目、结构化方案、全部真实求解代码 |
| 逐题技术路线图 | 对每个结构化子问题生成 | `figures/algo_problemN.png` | 该问方法、题目、该问真实代码 |
| 方法结构/机理图 | 仅当任务 `stage == proposed` | `figures/schematic_problemN.png` | 主题、提出方法任务、全局方法/基线/创新、代码、结果摘要、方法章节 |
| 额外示意图 | 仅当用户明确提出 | `figures/schematic_<id>.png` | 用户描述及可核验项目材料 |

技术路线和方法结构图是两种不同产物。不要因为某问已有技术路线图就省略已触发的 `proposed` 方法结构图，也不要把普通问题误判为 `proposed`。

以下内容不交给 image2：数据结果图、对比图、消融图、灵敏度图、收敛图、响应面、可行域、物理场、精确参数化几何及任何承担数值证据的图。这些必须由真实数据和可复现代码生成。

## 2. 来源优先级

总体技术路线图先用 LLM 综合“结构化方案 + 真实求解代码”总结有序步骤；失败时才从方案的 `subproblems` 和 `method` 字段回退。

逐题技术路线图先读取该问真实代码，从方法和执行顺序提炼模块；失败时回退为“输入数据 → 数据预处理与特征提取 → 建模 → 模型求解与训练 → 结果评估 → 结果输出”，并用该问实际内容替换通用词。

提出方法图按以下顺序汇总上下文：

1. 论文或研究主题；
2. 当前 `proposed` 任务的结构化方案；
3. 全局核心方法、基线与创新主张；
4. 真实实现代码，只据此识别模块和数据流；
5. 真实运行结果摘要，只用于确定输出或验证面板，不得虚构数值；
6. 已有方法章节，若与代码冲突以代码为准。

## 3. 提示词骨架

每张图都先写“内容规格”，再附“通用渲染约束”。把最终完整文本保存到与图片同名的 `.prompt.txt`。

### 总体技术路线图

```text
生成一张数学建模论文的总体技术路线图。依据下列题目、结构化方案和真实求解代码，准确表现各子问题的输入、研究内容、采用方法、问题间依赖和最终输出。采用横向四列式“研究技术路线/总体框架图”版式，列间关系清楚。不得添加材料中不存在的方法、数据或结论。

【题目】...
【结构化方案】...
【真实代码摘要】...
【必须出现的有序模块和连线】...
```

### 逐题技术路线图

```text
生成一张学位论文风格的“问题 N 求解技术路线图”。依据该问方法、题目和真实代码执行顺序，准确表现输入、预处理、建模、求解/训练、判断或迭代、结果评估和输出。采用淡蓝模块、清晰箭头和必要的虚线分组高亮。所有分支、回路和停止条件必须来自真实代码；不存在时不得虚构。

【该问题目】...
【结构化方法】...
【真实代码摘要】...
【必须出现的有序模块和连线】...
```

### `proposed` 方法结构/机理图

```text
生成一张与 CVPR/NeurIPS 方法总览图同等级的高信息密度横向结构图。忠实展开核心方法内部结构、真实分支、融合、反馈、输入、输出与验证面板。不要退化成简单的五步线性流程图，不要添加来源材料中不存在的模块、公式或实验结论。

【论文/研究主题】...
【当前提出方法任务】...
【全局核心方法、基线与创新主张】...
【真实实现代码识别出的模块与数据流】...
【真实运行结果摘要，仅用于输出/验证面板】...
【已有方法章节，冲突时以代码为准】...
【必须出现的模块、分支、融合、反馈和连线】...
```

### 通用渲染约束

```text
生成可直接用于论文的高质量科研图示：白色或浅色纯背景，无纹理和渐变；高对比、清晰锐利、留白充足；逻辑流向从左到右或从上到下；视觉层级明确且布局平衡。使用清晰一致的无衬线字体，所有标签在最终论文宽度下可读，文字保持水平，任何文字、节点和箭头不得重叠或裁切。准确使用科学符号、单位、图例和坐标；颜色采用色盲友好方案，并以形状或线型提供冗余编码，灰度打印仍可区分。不要使用无关装饰。图片内部不得出现“图1”“Figure 1”“Fig. 1”或正文式图题，图号和 caption 由论文排版层另行添加。所有中文、公式、上下标和希腊字母必须逐字准确，不得乱码或自造文字。
```

## 4. 用户回传协议

当前环境不能直接完成 image2 生成时，把完整提示词交给用户，并明确说：

```text
请将以上完整提示词交给 image2。生成后请提供原始 PNG（不要截图、不要压缩），我会继续检查科学关系、文字公式、重叠、裁切和论文最终尺寸可读性。当前状态为 WAITING_FOR_USER_IMAGE，图片返回并验收前不会写入论文。
```

不要把“提示词已完成”表述为“图片已完成”。用户返回文件后，将其复制到预定目标路径并保留 `.prompt.txt`。

## 5. 验收与返修

学位论文使用 8.0/10 门槛。按五项各 0-2 分评分：

1. 科学准确性：概念、符号和关系正确；
2. 清晰可读性：一眼可理解、层级清楚、无歧义；
3. 标签质量：关键元素完整、字号可读、风格一致；
4. 布局构图：流向合理、空间平衡、无重叠；
5. 专业外观：达到论文质量，线条锐利，颜色和对比恰当。

得分达到 8.0 才可标记 `ACCEPTED`。不足 8.0 时，从用户原提示词出发，只追加本轮发现的具体问题和必须保持不变的内容，形成返修提示词；最多组织两轮生成。第二轮仍未通过时标记 `REJECTED_AFTER_2_ROUNDS`，不得把问题图插入论文。
