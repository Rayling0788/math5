# MathModel Agent

面向 CUMCM、MCM/ICM、MathorCup 等数学建模竞赛的完整工作流 Skill。它以 MATLAB 建模计算和科研绘图为核心，串联题目与附件读取、模型设计、代码求解、结构化结果、论文写作、XeLaTeX/Typst 排版和最终逐页验收，并支持局部返工与按需多 Agent。

中文论文写作采用“证据锁定—自然改写—漂移复核”的保真流程：数值、单位、公式、场景和结论强度保持不变，以具体建模对象、推导动作和验证结果组织段落，同时清除聊天式修改痕迹、无来源权威和无证据拔高。该流程借鉴 `blader/humanizer` 的诊断思想并按数学建模论文重构，不机械套用英语禁词表，也不把技术文本改成口语化或人格化表达。

当前维护版本为 `v9.2.0`，对应分支 `version/v9`。历史版本通过版本分支、Git 标签和 GitHub Releases 保留。

## 安装

将仓库克隆到 Codex Skills 目录，并将文件夹命名为 `1start-mathmodel`：

```powershell
git clone --branch version/v9 https://github.com/Rayling0788/math5.git "$env:USERPROFILE\.codex\skills\1start-mathmodel"
```

如果该目录已经存在，请在原目录中更新：

```powershell
git -C "$env:USERPROFILE\.codex\skills\1start-mathmodel" pull origin version/v9
```

需要固定到本 README 对应版本时，可签出标签：

```powershell
git -C "$env:USERPROFILE\.codex\skills\1start-mathmodel" checkout v9.2.0
```

安装或更新后，在 Codex 新任务中输入 `$1start-mathmodel` 启动。建议先把题目、全部附件、参考论文和希望模仿的图片放入当前工作区，或在提示词中给出其完整路径。

## 三种执行模式

| 模式 | 适用场景 | 执行方式 | 高保真验证的地位 |
| --- | --- | --- | --- |
| `delivery` | 时间紧、先形成完整论文、已有项目需要继续交付 | 尽快建立真实的 MATLAB—结果—图表—论文闭环，再逐问补齐交付底线 | 可选增强验证不阻塞交付，但真实数据、完整回答、数值一致性、编译和逐页验收仍是硬要求 |
| `balanced` | 大多数正式竞赛，推荐主动选用 | 先完成可交付闭环，再对重要、敏感或高风险结论投入有界的增强验证 | 关键结论按风险升级，次要高保真任务不无限拖延整篇论文 |
| `certification` | 用户明确要求工程级、高保真、实验或严格认证 | 除完成论文闭环外，还必须通过事先声明的高保真门槛后才能采用相应最终结论 | 声明的认证门槛是阻断项；缺少数据、工具箱、实验条件或验证证据时必须报告阻塞，不能静默降级 |

如果只输入 `$1start-mathmodel` 而不指定模式，Skill 默认使用 `delivery`。出现“加快”“先完成论文”“继续交付”等要求时，也会切换到 `delivery`。选择 `balanced` 或 `certification` 时，最好同时说明截止时间、重点问题和必须通过的验证。

无论选择哪种模式，都不会降低以下底线：必须使用题目和附件中的真实数据，完整回答所有问题，保留可复现代码和结构化结果，保证论文数值一致，并完成最终编译和 PDF 逐页检查。三种模式的区别主要是可选高保真验证投入多少、是否阻断最终结论，而不是是否允许交付残缺论文。

## 最小启动示例

### Delivery：优先完成完整闭环

```text
$1start-mathmodel

使用 delivery 模式完成这道数学建模题。优先尽快形成可复现的 MATLAB—结构化结果—图表—论文闭环；可选高保真验证不得阻塞已满足交付底线的结果。使用中文 LaTeX 和 XeLaTeX 排版，完整读取题目与全部附件，所有问题都要回答，最后完成数值一致性检查、两遍编译和 PDF 逐页验收。
```

### Balanced：交付闭环后加强关键结论

```text
$1start-mathmodel

使用 balanced 模式完成这道数学建模题。先完成全部问题的 MATLAB—结构化结果—图表—论文闭环，再对影响最终结论的模型、参数、碰撞、极值或优化结果做有界的增强验证。采用中文 LaTeX 和 XeLaTeX 排版，按需启动 Agent，错误只返工受影响任务和页面，最终通过全部验证器和逐页视觉验收后交付。
```

### Certification：声明的认证门槛必须通过

```text
$1start-mathmodel

使用 certification 模式完成这道数学建模题。除完整 MATLAB 建模、论文和最终验收外，下列高保真验证属于最终结论的阻断门槛：
1. <填写必须通过的网格收敛、连续事件、独立算法交叉验证或实验验证>；
2. <填写必须满足的工程、物理或统计约束及容差>；
3. <填写必须覆盖的数据范围、极端场景和敏感性条件>。
任何门槛未通过时，不得把对应结果写成已认证或最终推荐值；应保留诊断证据并明确报告阻塞原因。论文使用中文 LaTeX 和 XeLaTeX 排版，全部问题和全部认证门槛通过后再交付。
```

`certification` 不是简单地“多跑几次”。启动时应尽量写清认证对象、判断阈值、验证方法和所需数据；否则 Skill 会先建立认证合同，再决定哪些结果可以进入摘要和最终建议。

## Balanced 完整启动模板

下面的模板可以直接粘贴到 Codex，再附上题目和附件。比赛类型、论文语言、排版引擎或软件要求不同时，可修改对应条目。

```text
$1start-mathmodel

使用 balanced 模式完成这道数学建模题。

要求：
1. 撰写完整中文数学建模论文，使用 LaTeX 和 XeLaTeX 排版，并采用比赛要求的正式论文模板。
2. MATLAB 负责全部建模、计算、优化、仿真、科研绘图和模型示意图，不得用手填结果或其他语言替代核心计算。
3. 完整读取题目及全部附件，建立输入清单和来源台账。附件已有真实数据时，不得使用代表值、典型值或虚构数据替代；外部补充数据必须注明来源、时间、单位和适用范围。
4. 使用按需多 Agent。只有在上游输入和任务边界明确后才启动对应 Agent，不要一次启动全部 Agent，不允许多个 Agent 同时修改同一文件。
5. 采用增量执行和局部返工。代码、图表、文字或排版发生错误时，只重跑直接受影响的任务和页面，不得从头重跑整个流程。
6. 每个问题都必须完整完成：问题分析、模型假设、变量定义、公式推导、算法设计、MATLAB 代码运行、结构化结果、约束验证、敏感性或稳健性分析以及论文图表。章节结构服从真实计算关系：顺序推导、单层估计和自然递推按动作链展开；只有变量族、约束族和目标/准则确需联立时，才在分别解释后写“模型汇总”，不得为统一格式虚构目标或重复上游模型。
7. 建模阶段参考我提供的图片风格，主动设计具有专业感的 MATLAB 模型可视化，包括参数化三维结构、结构剖面、响应曲面、可行域、空间场、网格或多视图组合图。图形必须由真实模型参数和计算结果生成，不得为了美观添加与模型无关的曲面或数据。
8. 在论文前部加入一张总体建模技术路线流程图，通常放在“问题分析”的总体思路之后、各问题分析之前。流程图应覆盖题目与附件输入、数据处理、各问题模型、问题间依赖、求解算法、验证和最终决策。
9. 所有核心图表必须保留 MATLAB `.m` 生成代码、源数据、矢量 PDF、300 dpi PNG 和图表清单记录。
10. 图表必须在原始尺寸和论文最终尺寸下分别检查中文字体、英文与数学字体、坐标轴、单位、图例、色条、箭头遮字、文字与图形重叠、标签裁切和可读性。
11. 所有重要结论必须形成“数据来源—模型公式—运行代码—结构化结果—验证—图表—论文表述”的可复现证据链，并区分理想上界、情景结果、可行容量和最终推荐结果。
12. 论文中的摘要、正文、表格、图题、结论和建议必须与 MATLAB 输出保持数值、单位、场景和候选方案一致，不得手工转录出相互冲突的结果。
13. 最终必须运行全部验证器，使用 XeLaTeX 连续编译至少两遍，检查交叉引用、参考文献、字体嵌入、编译警告和 PDF 完整性。
14. 将最终 PDF 全部页面栅格化并逐页检查封面、摘要、目录、正文、公式、表格、图片、流程图、图例、单位、页眉页脚、裁切、乱码和重叠问题。发现错误只返工对应模型、图表或页面。
15. 在所有问题、代码、图表、论文编译和逐页验收全部通过后才能交付，不得因时间或工具问题降低成品质量门槛。
```

## 常见续做方式

已有项目不需要重新开始。在提示词中指出当前状态和只允许返工的范围即可：

```text
$1start-mathmodel

继续当前数学建模项目，沿用 balanced 模式。读取已有 plan.md、todo.md、结构化结果和验收报告，保留已经通过的 Q1--Q3；只修复 Q4 图表与对应论文页面，除非共享输入、单位或公共方程发生变化，否则不得重跑其他问题。
```

仅重写论文而不重算时，可以直接说明：

```text
$1start-mathmodel

沿用已有 MATLAB 结果，只重写中文论文和必要图表，不重新计算已经接受的数值。冻结数值、单位、场景、假设和模型含义，但不要沿用原稿中难懂的小节顺序和公式墙；参照范文，从一个具体对象或局部构型开始，补出“已知什么—为什么列式—先求出什么—怎样推广—程序怎样求”的解法叙事。若现有报告和代码不足以支持推导，先补建模说明，不得编造。修改后只重新编译论文并检查受影响页面。
```

## 主要交付物

- `plan.md`、`todo.md`、输入清单、来源与参数台账；
- MATLAB 统一入口、各问题代码、测试和运行说明；
- CSV/JSON/MAT 等全精度结构化结果及结论台账；
- 图表生成代码、源数据、矢量 PDF、300 dpi PNG 和图表清单；
- 比赛正式模板下的论文源文件与最终 PDF；
- 分析建模、结果和最终验收报告；
- 题目要求的 Excel、提交表或其他指定结果文件。
